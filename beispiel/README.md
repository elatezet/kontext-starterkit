# Fiktives Designverzeichnis

Das gesamte Beispiel ist erfunden. Es enthält keine Kundenpersonen, realen Nutzungsdaten oder externen Fachstandards. Auch festgelegte Angaben sind ausschließlich Setzungen innerhalb dieser Übung. Die leeren Vorlagen liegen außerhalb dieses Ordners.

Lest [Grundlagen](grundlagen.md) und [Methode](fachwissen.md) als Ebene 1, dann [Projektstand](projekt.md) und [Entscheidung](entscheidung.md) als Ebene 2. Bearbeitet die [Aufgabe](aufgabe.md) als Ebene 3 mit dem [Aufgabenprompt](../prompts/aufgabe-bearbeiten.md).

Die Aufgabe prüft den Leerzustand eines kleinen Designverzeichnisses. Der Projektumfang legt fest, welche Funktion existiert. Die Methode bestimmt, wie ihr deren Text prüft. Alle Beispiel-Dateien bleiben mit `geprueft_am: offen` gekennzeichnet; ein erfundenes Szenario ersetzt keine Prüfung an einem realen Produkt.

Für einen zweiten Durchlauf könnt ihr in einer eigenen Kopie den Beschluss ändern: Das Produkt behält jetzt die Suchphrase beim Zurücksetzen der Filter. Aktualisiert Entscheidung und Projektstand gemeinsam. Lest den Bestand erneut ein und prüft, ob ein Text weiterhin fälschlich verspricht, alle Einträge zu zeigen. Diese Übung beschreibt einen Prüfauftrag und behauptet keinen ausgeführten Modelltest.
